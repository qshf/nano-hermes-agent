# v23.2 — 项目上下文注入 + --cwd 启动

> 实现日期：2026-05-29
> 分支：`delegate/v0.23.2`
> 基于：`delegate/v0.23.1`（v23.1 批量并行 + 工具白名单）

## 这一档解决什么

V0–V23.1 的硬约束：**agent 必须在 nano 仓库根目录下启动**。`skills/` 路径
是 `Path(__file__).parent` 还能跑，但 system prompt 里**没有任何"用户项目"
的信息**——agent 不知道当前 cwd 是哪个项目、有什么约定、用什么工具链。

用户把 nano 拉进 `/Users/foo/Documents/book/` 想让它写书时，第一个动作
是 `cd nano_hermes_agent && python main.py`，结果 agent 去操作的是 nano
自己的源码而不是 `book/`，并且 system prompt 里没有 `book/` 项目的任何
约定信息。

V23.2 让 agent 真正"跨项目可用"：

```
python /path/to/nano/main.py --cwd /Users/foo/Documents/book
```

启动后：
- `os.chdir(book/)` → terminal / read_file 等工具的相对路径都在 `book/` 下
- system prompt 自动注入 `book/nano-hermes-agent.md`（首选）或 `book/AGENTS.md`
- skills/ 仍从 nano 自己源码目录加载（agent 自带能力，跨 cwd 不变）

## 关键设计决策

### 1. 文件名优先级：`nano-hermes-agent.md` → `AGENTS.md`

**选了什么**：两档优先级，第一个命中即停。

**为什么不收 `CLAUDE.md`**：用户明确选了"nano 自己的命名"。`CLAUDE.md`
被很多项目（包括 nano 自己仓库）已经占用作"给 Claude Code 的项目说明"
——如果 nano agent 也读 `CLAUDE.md`，会和 Claude Code 互相污染（Claude Code
看到的是 Claude Code 用的指引，nano agent 看到的也是同一份，但语义不一定
对得上）。专属命名 `nano-hermes-agent.md` 让两套 agent 互不打扰。

**为什么 `AGENTS.md` 作 fallback**：`AGENTS.md` 是源项目 hermes-agent 也支持
的通用命名（[hermes-agent/agent/prompt_builder.py:1356](.../hermes-agent/agent/prompt_builder.py#L1356)），
跨 agent 工具的事实标准之一（OpenAI Codex / Aider 等也读这个）。同一个
项目里写一份 `AGENTS.md` 给所有 agent 用，是更经济的常态。

**为什么不走到 git root**：源项目的 `.hermes.md` 会从 cwd 一路 walk 到
git 根目录（`hermes-agent/agent/prompt_builder.py:99`）。教学版有意简化：
**只看 cwd 那一层**。如果用户希望子目录有自己的上下文，建议用绝对路径
启动（`--cwd <subdir>`）而不是依赖隐式上溯。代码量从 ~50 行降到 ~15 行，
教学价值更高。

### 2. `--cwd` 在模块顶层处理（不在 `run_agent()` 里）

**选了什么**：`main.py` 顶层 `_parse_cli_args()` 后立刻 `os.chdir`，**早于
`PromptBuilder` 构造**。

**为什么**：模块顶层早就构造了 `prompt_builder = PromptBuilder(...)` —— 这
是 V23.0 setter 注入 delegate context 时为了"父子 agent 共享同一份 builder"
留下的形态。如果把 `chdir` 放进 `run_agent()`，PromptBuilder 在 `chdir` 之前
就已经把 `cwd=Path.cwd()` 抓死了，`--cwd` 完全失效。

**fail-fast 校验**：`--cwd <bad>` 直接 `sys.exit(2)`，不进 agent loop。
理由：`os.chdir` 失败比"chdir 成功但目录是个奇怪的临时挂载点"更明显，
但**校验阶段 `is_dir()` 失败时让用户立刻看到原因**，避免后续诡异路径错
（"为什么 read_file 找不到我的文件？"）。这是源项目同样做法
（`hermes-agent/hermes_cli/main.py:9822` 的 `--cwd`）。

### 3. 段位置：骨架之后、skill 索引之前

**选了什么**：`build()` 段顺序 = `骨架 → 项目上下文 → skill → memory → tools`。

**为什么不放最前**：骨架是 agent 身份段（"You are a helpful coding
assistant"），项目上下文是身份的**延伸**（"在这个项目里你的具体角色"）。
骨架在前更符合人读 prompt 的认知顺序。

**为什么不放最后**：靠近末尾的内容容易被 LLM 给低权重（"中间遗忘"
现象）。项目上下文里通常是最重要的项目约定（用什么工具链、不要碰什么
文件、风格偏好），必须靠近骨架。

**对 V20 prompt cache 的影响**：cwd 变化 → 项目上下文段变化 → cache
prefix 字节失配。这是预期：**不同项目本就不该共享 cache**。同一个
cwd 内多轮对话，prefix 仍然稳定，cache 命中不受影响。同 cwd 的纯函数
性质有 `test_build_is_pure_with_cwd` 保障。

### 4. 不做的事（明确划出范围）

- **不做子目录渐进发现**（源项目 `subdirectory_hints.py`）：agent 进 `src/`
  时追注 `src/AGENTS.md`、进 `tests/` 时追注 `tests/AGENTS.md`。这要改
  消息流（每次 tool call 后检测 cwd 变化、追加新 system 消息），代码量
  跟 v23.2 当前总量相当，划到 v23.4 单独做。
- **不做 prompt-injection 扫描**（源项目 `_scan_context_content`）：扫描的是
  AGENTS.md 里有没有"忽略前面所有指令"之类的注入串。教学版省略；用户
  自己写的 AGENTS.md 默认可信。
- **不剥 YAML frontmatter**（源项目 `_strip_yaml_frontmatter`）：源项目预留
  给"未来 PR 把 frontmatter 当结构化配置"。教学版还没用上，省略。

## 真实踩坑

### 坑 1：模块顶层执行 `os.chdir` 撞到 `import`

```python
from agent import PromptBuilder, SkillLoader   # 这一行先跑
# ... 然后才到
_cli_args = _parse_cli_args()
os.chdir(_cli_args.cwd)
```

`from dotenv import load_dotenv; load_dotenv(override=True)` 必须**在 chdir
之前跑**，因为 `.env` 加载用的是当前 shell cwd（如果用户 `python /path/to/main.py`
不带 `--cwd`，但当前 shell 在 nano 目录下，`.env` 还是能加载）。chdir 之后
再去找 `.env` 就找不到了。

**最终顺序**：`load_dotenv()` → 解析 argparse → `chdir` → 其他 import。
nano 的所有功能模块（`memory`、`transports`、`tools`）都不依赖 cwd（全是
`Path(__file__)` / 绝对路径），所以 chdir 之后 import 也安全 —— 这是
V23.2 能这么干净落地的前提。

### 坑 2：`Path.cwd()` 在 `argparse` 之前会抓错

构造 `PromptBuilder(cwd=Path.cwd())` **必须**在 `os.chdir` 之后；如果用
`os.getcwd()` 也是同理 —— 但选 `Path.cwd()` 是和源项目 `_load_hermes_md`
的 `Path(cwd).resolve()` 同向（resolve symlinks，避免后续路径比较时踩坑）。

### 坑 3：测试用 subprocess 起 main.py 验 fail-fast，需要绝对 cwd

`test_main_py_rejects_bad_cwd` 用 `subprocess.run(... cwd=str(nano_root))`。
原本写的相对路径会在 subprocess 跑时被 pytest 工作目录截胡，导致 main.py
找不到 import。统一用 `Path(__file__).resolve().parent.parent` 解决。
