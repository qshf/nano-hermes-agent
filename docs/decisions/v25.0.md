# v25.0 — trajectory 训练样本导出（数据飞轮起点）

> 把跑过的对话在被丢弃前自动落成 ShareGPT 格式的 SFT 样本。新建 `agent/trajectory.py`
> + `agent/redact.py`，在三个"会话即将消失"的时机 flush：压缩点 / 退出兜底 / 子 agent 结束。

---

## 0. 一句话

v24 让对话能 **resume**（状态回放），v25.0 让对话能 **train**（数据飞轮）—— 两者形态正交，
各落各的盘。

---

## 1. 决策清单

### 决策 1：trajectory 与 session-store 是两套正交持久化，不复用 v24 的盘

| 维度 | v24 session-store | v25 trajectory |
|------|-------------------|----------------|
| 形态 | OpenAI messages dict（SQLite 逐条入行） | ShareGPT `{from,value}` 对（jsonl 逐行一对话） |
| tool | tool_calls + tool_call_id 完整关联 | 拍平成 `<tool_call>` XML，**丢 tool_call_id** |
| 密钥 | 原样（能 replay） | 过 redact **脱敏**（内容已变） |
| 用途 | 状态回放 — resume 真能续上 | 数据飞轮 — 喂 SFT，replay 会断 |

**为什么不复用**：trajectory 丢了 tool_call_id（tool 结果配不回调用）+ 密钥被脱敏（内容变了），
拿去 replay 必断。它只配训练，不配恢复。强行共用一张表会让两个关注点互相拖累。

### 决策 2：选 ShareGPT 格式，一行一个完整对话

ShareGPT（`{conversations:[{from,value}]}`）是 `trl`/`axolotl`/`LLaMA-Factory` 的事实标准输入。
jsonl **一行一个完整对话** —— 这条约束决定了 flush 粒度必须是"整段会话"而非"轮末增量"
（轮末 append 会切出半截对话碎片，破坏"一行一对话"语义）。

### 决策 3：密钥脱敏默认开 + import 时快照

每条 value 落盘前过 `redact()`（~10 条 pattern：`sk-*`/`ghp_*`/JWT/Bearer 头/`KEY=value`/
私钥块/DB 连接串）。`NANO_REDACT_SECRETS=0` 才关，且 `_ENABLED` 在 **import 时**取快照
（对齐源 `redact.py:67`）—— 防"运行期代码偷偷 `os.environ[...]='0'` 把脱敏绕过"。
代价：测试验"关闭"行为得 reimport（test 第 7 项用快照不变来验证这个契约本身）。

### 决策 4：completed 分流 samples / failed，截断 think 不污染训练集

`completed=True` 且无残缺 `<think>` → `*_samples.jsonl`；否则 → `*_failed.jsonl`
（对齐源 `trajectory.py:42`）。截断的 reasoning（`<think>` 开标无闭合）会教模型"不闭合 think 块"，
必须挡在训练集外。中途 `quit`/`Ctrl+C` 留下的半截对话自动落 failed。

### 决策 5：三个 flush 点 —— 覆盖"会话消失"的全部出口

| flush 点 | 位置 | 时机 | completed |
|----------|------|------|-----------|
| 压缩点 | `compaction.py` `store.append` 之后 | 旧段被压缩摘要替换前 | True（这段跑完了） |
| 退出兜底 | `main.py` finally `session_store.close()` 之后 | 进程退出 | True（正常退出） |
| 子 agent | `delegate_tool.py` `_accumulate_runtime_tokens` 之后 | 子 loop 返回 | `exit_reason=="completed"` |

压缩点落"被分裂走的旧段"，退出兜底落"最终段"，两点合起来覆盖主 agent 全程；
第三点是子 agent（见决策 6）。三处都包 try，**trajectory 落盘永不阻断主流程**。

### 决策 6：子 agent 轨迹落盘 —— nano 在此**超越源项目**

源项目 delegate（`hermes-agent/tools/delegate_tool.py:1090` 构造 child `AIAgent` 时
**缺省 `save_trajectories=False`**，见 `run_agent.py:1066` 默认值）让子 agent 中间步**直接丢弃**，
只把 summary 回传父。子的 tool 调用序列往往是**最干净的训练样本**（目标明确、上下文窄、
无父对话噪声）—— 丢掉等于丢掉飞轮最优质的燃料。

> ⚠️ 论据校正：曾误以为证据在 `batch_runner.py:331`，但那是**批处理入口**，它反而通过
> `_convert_to_trajectory_format(result["messages"])` **捕获了完整轨迹**。真正"丢子轨迹"的
> 是 delegate 路径的缺省 `save_trajectories=False`。引用以此为准。

**隐藏前置成本**：要落子轨迹得先让子把 messages 交回来。nano `child_loop._build_result`
（9 处 return 共用）原本只回 `summary/tool_trace/tokens` —— `tool_trace` 是轻量摘要，转不出
合格样本。v25.0 给 `_build_result` **加 `messages` 字段**（浅拷贝防 mutate，早退路径落空列表），
9 处调用点统一补 `messages=messages`。这步不做，决策 6 无从落地。

### 决策 7：`:none:` sentinel 关闭落盘，与 `:memory:` 区分

`TRAJECTORY_DIR=:none:` → `save_trajectory` 返回 None 不落盘。这是 nano 自创 sentinel，
与 session_store 的 `SESSION_DB_PATH=:memory:` 刻意区分：一个**退化到不落盘**，
一个**落内存库**（仍可 query）。两者语义不同，不混用同一个标记。
