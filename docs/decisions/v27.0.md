# v27.0 — LLM ProgressSupervisor MVP（废弃实验）

> 本档保留为废弃记录。v27.0 曾把 v26.5 的“事件驱动语音进度”重做成 `AgentEventBus → ProgressSupervisor → LLMPhraseProvider → VoiceClient`，功能可跑，也证明了中立事件边界有价值；但它仍把播报策略、文案 LLM、cooldown、heartbeat 与工具价值判断放在主 agent 进程里，因此不作为主线继续演进。

---

## 0. 一句话

v27.0 的正确资产是“运行事实事件化”和“payload 安全边界”；错误是让宿主 Runtime 继续拥有语音策略。主线已切到 [v27.1](./v27.1.md)：host 只发送 bounded envelope + runtime phase lease，外部 Voice Orchestrator 负责是否播、播几次、何时播、怎么播。

---

## 1. 当时为什么做

v26.4 `VoiceHeartbeat` 只能在长等待期间固定说“还在处理”，缺少上下文。v26.5 尝试更丰富的进度播报，但把 voice emit 散落在 `main.py` / delegate / slash / tool 路径里，污染主流程。

v27.0 因此先补了一个中立事件边界：`AgentEventBus`。这个方向保留。

---

## 2. 废弃原因

v27.0 可运行，但架构仍不达标：

- `ProgressSupervisor` 在宿主侧硬编码高价值工具、低价值工具、错误播报、debounce、每轮播报次数；
- `LLMPhraseProvider` 复用主 agent transport chain 生成语音短句，让主进程为语音文案再发起模型调用；
- `main.py` 需要初始化 voice client、探测 voice-runtime、维护 fallback heartbeat；
- memory tools 绕过 registry，导致 `main.py` 继续出现语音相关补丁；
- assistant 仍被 `voice-runtime` skill 指令要求调用 `nano-voice-say`；
- 长工具参数生成、父进程等待子 agent 等“运行中 phase”仍不能被外部服务独立调度。

这些问题说明 v27.0 只是把“模型调用语音工具”的耦合迁移到了“宿主 Python 策略”，没有彻底解耦。

---

## 3. 保留资产

保留并迁移到 v27.1 的内容：

- `AgentEventBus`：中立 observer substrate，listener 失败不影响主流程；
- 安全 payload 原则：不发送 raw args、raw output、文件内容、密钥、栈追踪、完整用户 prompt；
- 元调度层发运行事实的思路：tool/slash/delegate/main 只报告事实，不报告语音意图；
- 失败隔离原则：任何语音/observer side-channel 都不能影响主 turn。

---

## 4. 废弃内容

主线不再使用：

- `agent/progress_supervisor.py`
- `agent/llm_phrase_provider.py`
- `VOICE_LLM_*` 宿主侧短句 LLM 配置
- `ProgressSupervisor.create_if_available(...)`
- host fallback 到 `VoiceHeartbeat` 自动播报的 v27.0 接入路径
- assistant 通过 `terminal` 调用 `nano-voice-say` 的 directive

`VoiceHeartbeat` 文件暂作为 v26.4 legacy 代码保留，但 v27.1 orchestrator enabled 时不再由主线自动 fallback。

---

## 5. 验证历史

v27.0 当时新增的不变量测试证明了以下内容可行：

- event bus listener 隔离；
- 工具/slash/delegate lifecycle 可发安全事件；
- host-side supervisor 可降噪、fallback、heartbeat。

但这些测试断言的是已废弃的宿主侧播报策略，因此后续替换为 v27.1 envelope / phase lease / sink fail-safe 测试。

---

## 6. 结论

v27.0 不是失败的方向，而是一个有价值的中间实验：它验证了“事件化”是正确的，也暴露了“宿主侧策略”仍然耦合。v27.1 在此基础上切到外部 Voice Orchestrator。
