# v26.3 — 行为指令注入 system prompt（inject_directive）

> skill 现在能在 frontmatter 声明 `inject_directive`，把一段「行为纪律」提到
> system prompt 常驻段，让 agent **每轮都看得到、不依赖先调 skill_view**。这是
> 渐进式披露的「常驻例外」，专为「需要主动触发」类能力（语音播报）而设——光靠
> tier 1 一行 description 驱动不了主动行为。

---

## 0. 一句话

v26.0~v26.2 解决「skill 能带什么、声明什么、引用什么」；v26.3 解决「skill 怎么
让 agent **主动用它**」——把强制纪律从 tier 2 正文（平时不读）提到常驻区（每轮可见）。

---

## 1. 触发动机：语音播报 agent 不主动播

接入 `nano_voice_kit` 后实测发现：agent 只在用户**明说**「调用语音播报」时才播报，
普通任务里完全不主动。根因是 nano 的渐进式披露 + 强制纪律放错了层：

- system prompt 里 voice-runtime 只呈现为 tier 1 一行 description。
- 「必须播报」的强制纪律全写在 SKILL.md 正文（tier 2）。
- 但 agent 只有**已决定用语音**时才会调 skill_view 读正文 → 死锁：
  它不知道有「必须主动播报」的义务，自然不会去读那条义务。

源项目 streamvox 的 SKILL.md 用大量「强制检查点」「必须」措辞驱动主动播报，但
那依赖宿主把 SKILL.md 正文常驻在上下文里——nano 的渐进式披露不会。所以**光抄
措辞无效**，必须解决「纪律出现在 agent 每轮可见处」这个结构问题。

---

## 2. 决策清单

### 决策 1：做通用 `inject_directive`，不为 voice 硬编码

prompt_builder 里直接写个 voice 专属段也能解决，但那把 nano 核心 prompt 跟
voice kit 耦合死。选通用机制：任何 skill 都能声明 `inject_directive`，渲染层
统一处理。代价是多一个 frontmatter 字段 + 一个渲染段；收益是解耦 + 可复用 +
符合 nano「能力即 skill」的教学主轴。

### 决策 2：注入门槛比 tier 1 索引更严（is_fully_available）

tier 1 索引的门控（v26.1）：requires_tools 满足就进索引，env 缺失仅软标记。
但 directive 是「命令 agent 主动用这个能力」——能力真用不了（缺 env / 缺 tool）
还命令它「必须用」是有害的（agent 会反复试一个注定失败的命令）。所以注入门槛是：

- `missing_env_vars()` 为空（required env **全设**），**且**
- requires_tools 全在当前可用工具里（`available_tools=None` 时不卡这条，向后兼容单测）。

实测反例验证：不设 `DASHSCOPE_API_KEY` 时 directive 段为空，但 skill 索引仍保留
voice-runtime + setup 软标记——两层逻辑各司其职（索引引导配置，directive 驱动使用）。

### 决策 3：directive 要短，写进决策日志当约定

`inject_directive` 把内容塞进**每轮**的 system prompt，有 token 成本 + 占 prompt
cache 前缀。约定：只给「真正需要主动触发」的少数 skill 用，每段尽量短，详细规则
仍留在 tier 2 正文（directive 末尾引导「按需 skill_view 读正文」）。这是约定不是
强制——nano 教学版不做「directive 长度上限」这类机制（YAGNI）。

### 决策 4：不破坏 prompt cache

directive 段的内容只取决于「哪些 skill 完全可用」，同一 cwd + 同一 env 下稳定，
所以该段在会话内稳定，不会每轮 thrash 缓存。段位置固定在 skill 索引之后、memory
之前（memory 段本就每轮变，directive 在它之前不影响 memory 之后的动态区）。

## 3. 落地

| 文件 | 改动 |
|------|------|

段顺序：骨架 → 项目上下文 → skill 索引 → **行为指令** → memory → 工具列表。

## 4. 验证

- 不变量 10/10（解析 + is_fully_available 门控 + 渲染过滤 + 向后兼容空段）。
- 回归：v26.1（10/10）、v21.2 prompt_builder（15/15）无破坏。
- 真机：`DASHSCOPE_API_KEY` 设了 → directive 进 system prompt；不设 → directive
  消失但索引保留软标记。
