# v27.3 — voice_say 结果朗读 + self-narrate 让位

> 本档记 **nano 主仓**这一侧：`voice_say` 工具 + `voice-result-readout` skill + 与
> v27.1 禁令的边界调和。配套的 orchestrator 侧「self-narrate 让位」策略记在
> `nano_voice_kit` 的决策日志（host 已发事实，策略层兑现）。

---

## 0. 一句话

给主 agent 加一个**唯一**的语音工具 `voice_say`：**仅当用户显式要求**时朗读**最终结果**摘要。
这是 v27.1「主智能体零语音工具调用」的**正交例外**，不是推翻 —— v27.1 禁的是「自主播**进度**」，
本工具做的是「用户点名要的**结果朗读**」，两者职责正交。

---

## 1. 为什么需要这个例外

v27.1 把进度播报整体外移给 Voice Orchestrator，host 只发 bounded envelope。但 orchestrator
**物理上拿不到完整答案** —— 它只收受限事实预览（截断、脱敏、字段白名单）。所以当用户说
「把结论念给我听」时，orchestrator 没法替 agent 念结果，**只有 agent 自己持有完整交付物**。

这是一条 v27.1 没覆盖的缝：进度归外部，结果朗读归谁？答案只能是 agent 本人。于是开一个
**窄到不能再窄**的例外，并用三道闸把它焊死在「结果朗读」上、绝不漏成「进度播报」。

---

## 2. 为什么是「工具」而不是让 agent 拼 terminal

用 terminal 拼 `nano-voice-say --text "..."` 本就能做，但：

- 中文 + 引号转义易错，失败退出码混在 terminal 输出里，agent 难判断成没成。
- 没有可测路径 —— 注册、降级、空文本、intent 兜底都无法 assert。

收成一个工具：一次调用、无 shell 转义、失败结构化降级、registry dispatch 有测试路径。

---

## 3. 落地

### 3.1 `tools/voice_say_tool.py`（新）

- **连接方式**：subprocess 调 `nano-voice-say` 二进制，**不 import nano_voice_kit** —— 两仓保持
  解耦。二进制路径走 env `NANO_VOICE_SAY_BIN`，默认指向 voice_kit 的 `.venv/bin/nano-voice-say`。
- **降级隔离**：Runtime（:8920）没起 / 二进制不存在 / 超时 → 全部捕获成
  `tool_result(output={"spoken": false, "reason": ...})`，**语音不可用绝不掀翻 agent 任务**。
- **空文本**：是用法错误（非降级）→ 走 `tool_error` 独占 error 语义，不混进 `spoken=false`。
- **intent**：枚举 `info/progress/warning/urgent/done`，非法值兜底 `info`（不报错）。
- 自注册：`registry.register(VOICE_SAY_SCHEMA, voice_say_handler)`，进 `core` + `docker` toolset。

### 3.2 触发边界三道闸（防漏成进度播报）

1. **工具 description**：`"Call this ONLY when the user has explicitly asked..."` +
   `"Speak the RESULT/summary, never progress"` + `"Do NOT call this proactively"`。
2. **`skills/voice-result-readout/SKILL.md`（新）**：`metadata.requires_tools: [voice_say]` 门控，
   正面清单（「念给我听」「播报总结」）+ 负面清单（❌进度 ❌不自主 ❌长文）+ 失败处理。
3. **`skills/voice-runtime/SKILL.md`（改）**：原 `inject_directive` 绝对禁「不要调用
   nano-voice-say」，会和新工具打架（directive 是 v26.3 常驻注入，模型同时看到禁令和许可会困惑）。
   改成**只禁进度播报** + 显式标注「唯一例外：用户显式要求朗读结果时用 `voice_say`，与进度播报正交」。

## 4. 配套：orchestrator 的 self-narrate 让位（记在 voice_kit，这里说为什么）

**问题**：agent 调 `voice_say` 念完结果后，host 的 side-channel 仍会发 `turn_finished` envelope，
orchestrator 据此又播一句「任务完成」—— **重复**。最荒唐时序：agent 已念完整首诗，喇叭紧接着
冒一句「诗写好了，我这就念给你听」。

**修在哪**：纯 orchestrator 侧（`SpeechPolicy`），nano 零改动 —— 因为信号
`activity.name=voice_say` **本就在 host 发的 envelope 里**，符合 v27.1 分工（host 发事实，
orchestrator 定策略）。本轮一旦 `decide()` 看到自播工具名 → 置 `agent_self_narrated` 标志 →
后续所有事件（含 `turn_finished`、heartbeat 重播）一律 silent。换轮 `_roll_turn` 清零。

**诚实的限制**：若 `turn_started` 那句开场在 `voice_say` **之前**已发出，物理上收不回 ——
那时 orchestrator 还不知道本轮会自播。要连开场也消除，需 nano 在 turn_started 时预告「本轮将
自播」（预测性强、违背 host 零改动），故未做。当前能掐掉的是 voice_say **之后**的所有句子
（含最扎耳的 post-readout `turn_finished`），3 句口水话 → 1 句。

## 5. 测试

`scripts/test_v27_3_voice_say.py`（4 项不变量，全程不碰真喇叭 —— `NANO_VOICE_SAY_BIN`
指向必定不存在的路径，验证降级路径）：

1. `voice_say` 注册进 registry，且在 `core` + `docker` toolset。
2. 二进制不存在 → `spoken=false` + reason，**绝不抛、绝不让任务崩**。
3. 空文本 → `tool_error`（无 `spoken` 键，独占 error 语义）。
4. 非法 intent → 兜底 `info`，不报错。

**回归**：`test_v27_1_voice_orchestrator.py` 17/17 不变（host envelope 边界没被这版动）。
voice_kit 侧 self-narrate 让位由 `test_orchestrator_mvp.py` test_24/25/26 守（纯策略让位 /
换轮重置 / HTTP 端到端复刻 poem 场景）。

**验收（FR-5，人耳）**：起 :8920 runtime + orchestrator，agent 完成一个任务后用户说「念给我听」，
听到 agent 用 `voice_say` 念结果摘要，且 orchestrator **不再**追播 turn_finished。

---

## 6. 诚实的取舍

- 开场句收不回（见 §4 限制），可接受 —— 它在结果朗读**之前**，不构成「念完还说我这就念」的尴尬。
- `voice_say` 默认二进制路径硬编码到 voice_kit 的 `.venv`，跨机器需改 `NANO_VOICE_SAY_BIN`。
  联调够用；真分发应做成可发现路径或配置。
- 自播工具集 `{voice_say}` 可经 env `VOICE_ORCHESTRATOR_SELF_NARRATE_TOOLS` 扩展，要彻底关闭
  让位可设一个不存在的工具名。
