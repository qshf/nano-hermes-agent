# v26.0 — bundled 资源发现 + tier 3 读取 + 路径沙箱

> skill 从「单个 SKILL.md」升级为「目录包」：`SKILL.md` 是入口（tier 2），它携带的
> references/templates/assets/scripts 是 tier 3，按需再展开。`skill_view(name, file_path)`
> 双模式 + `..`/symlink 双防线沙箱。计划见
> [docs/Skill-system/skill-system-completion-plan.md](../Skill-system/skill-system-completion-plan.md) §5。

## 0. 一句话

v21.3 让 skill 能两层加载（索引 → 全文），v26.0 让 skill 能**携带资源**——
模板/参考/脚本不再被迫塞进 SKILL.md 正文，progressive disclosure 多出第三层。

## 1. 决策清单

### 决策 1：资源读取复用 `skill_view(name, file_path)` 双模式，不开独立工具

voice-kit-plan 原设想一个独立的 `skill_resource_read` 工具。对照源项目
[hermes skills_tool.py:1086-1185](/Users/qshf/my-project/hermes-agent/tools/skills_tool.py)
发现源项目**没有独立工具**，而是给 `skill_view` 加可选第二参数 `file_path`：

| 维度 | 无 `file_path`（tier 2） | 有 `file_path`（tier 3） |
|------|--------------------------|--------------------------|
| 读什么 | SKILL.md 全文 | 那一个 bundled 资源 |
| 附加 | `linked_files` + `usage_hint` 引导 | `file` + `is_binary` 字段 |

**为什么不拆两个工具**：一个工具两种模式比两个工具更省 LLM 的工具选择负担，
且让 tier 2→tier 3 是同一心智模型的延伸（「看说明书」→「翻说明书引用的附录」）。

### 决策 2：两道沙箱防线内联进 `read_resource`，不抽 path_security 模块

源项目有独立的 `tools/path_security.py`。nano 教学版把两道防线内联（~6 行看得见逻辑）：

- **防线 1**：`".." in Path(rel_path).parts` —— 在 resolve 前先拦字面量 `..`（最常见攻击，错误信息最直观）
- **防线 2**：`(skill_dir / rel_path).resolve()` 后校验仍以 `skill_dir.resolve()` 为前缀 —— 拦 symlink 指向目录外的逃逸

两道缺一不可：只有防线 1 挡不住 symlink（`assets/leak -> /etc/passwd` 里没有 `..`）；
只有防线 2 时 `../../etc/passwd` 也能被 resolve 前缀校验挡住，但防线 1 让最常见的攻击早失败、错误更清晰。

### 决策 3：binary 文件只回尺寸标记，不回字节

`read_resource` 用 `read_text(utf-8)`，`UnicodeDecodeError` 即判定 binary，
返回 `[Binary file: name, N bytes]` 而非原始字节——避免图片/二进制污染 context
（也避免 JSON 序列化炸控制字符）。`is_binary=True` 让调用方明确知道这是标记不是内容。

### 决策 4：扩展名白名单收紧，但沙箱不依赖白名单

`list_resources` 的发现层按子目录用扩展名白名单（references 限 `*.md/*.txt`，
scripts 限脚本语言，assets 放行 `*`）——白名单之外的文件（如 `references/note.log`）
不进 `linked_files`，省 context。但 **`read_resource` 的安全不依赖白名单**：
沙箱靠两道路径防线，agent 仍可显式读任意沙箱内文件（白名单只管「主动推荐什么」）。

### 决策 5：scripts/ 只发现不执行

`scripts/` 下的 `*.py/*.sh/...` 收进 `linked_files["scripts"]`，但**从不自动执行**。
agent 要跑某脚本时走它本就有的 terminal 工具显式调用。与源项目行为一致，
也是 §8 安全护栏（「skill ≠ 任意代码执行」）的一环——本档连「执行」的代码路径都不存在。

## 3. 裁剪（vs 源项目）

- 不抽独立 `path_security.py` 模块——两道防线内联（决策 2）
- 不做 `assets/` 的 MIME 嗅探，binary 一律尺寸标记
- 不做 index-cache 磁盘快照（源项目对 100+ skill 必需，nano 不需要）
- 目录层级保持一级 `skills/<name>/`，不升级两级 `<category>/<name>/`

## 4. 验证

`scripts/test_v26_0_skill_resources.py` —— 10/10 不变量：

- **list_resources**（3）：无资源→空 dict；四类资源→key 排序、路径相对 skill_dir；白名单外扩展名→不收
- **read_resource 沙箱**（4）：字面 `..`→ValueError；正常文本→`(content, False)`；不存在→FileNotFoundError；symlink 逃逸→resolve 后 ValueError
- **skill_view 双模式**（3）：无 file_path→含 linked_files+usage_hint；有 file_path→只回该文件+file 字段；binary→is_binary=True 且 output 不含原始字节

回归：`scripts/test_v21_3_skill.py` 13/13 仍通过（同文件无破坏）。

真跑：`SkillLoader('skills')` 对真实 `plan` skill →
`list_resources('plan')` 得 `{'references': ['references/checklist.md']}`，
`../../../etc/passwd` 与 `../plan/SKILL.md` 均被防线 1 拦截。

## 5. 决策一句话总结

| 决策 | 选项 | 没选 | 原因 |
|------|------|------|------|
| 资源读取入口 | `skill_view(name, file_path)` 双模式 | 独立 `skill_resource_read` 工具 | 源项目实证更省 LLM 工具选择负担 |
| 路径沙箱 | 两道防线内联 read_resource | 移植 path_security.py 模块 | 教学场景 6 行看得见逻辑 |
| binary 处理 | 只回尺寸标记 | 回 base64 / 字节 | 防 context 污染 + JSON 序列化安全 |
| 白名单角色 | 只管发现层推荐 | 也作为读取层安全边界 | 安全靠路径防线，白名单管「推荐什么」 |
| scripts 执行 | 只发现不执行 | 自动执行 | skill ≠ 任意代码执行（安全红线） |
