# v26.4 — 代码级语音心跳：长任务防"挂机"感知

> v26.3 用 prompt 软指令命令模型「每 20 秒自心跳」。问题不是措辞弱，是**结构性
> 做不到**：模型在 terminal 阻塞期、token 生成期物理上无法插播，且只在轮间有机会
> 动作还经常忘。本档把「存活心跳」从模型手里拿走，交给 agent 主进程的后台守护
> 线程——它直连 `nano_voice_kit` 的 `VoiceClient`，在主线程被工具卡住那几十秒里
> 照常报活。模型只保留有语义的播报（起手 / 阶段 / 风险 / 完成）。

---

## 0. 一句话

v26.3 解决「让纪律每轮可见」；v26.4 解决「让纪律里那条做不到的（定时报活）由代码
兜底」。把"每 N 秒必须出声"这个对模型不可能的硬要求，换成代码层保证。

---

## 1. 触发动机：长任务里用户以为服务挂了

实测痛点：跑长命令 / 多步检索时，agent 长时间不出声，用户以为挂机。v26.3 让模型
「主动每 20s 播心跳」，但有三个物理死穴：

1. **terminal 阻塞期模型不能动**。`tools/terminal_tool.py` 的 `subprocess.run(timeout=30)`
   一旦跑个长命令，主线程整个卡住——而这正是"最像挂机"的时刻，模型恰恰这时哑火。
2. **模型自己生成 token 期间也不能插播**。
3. 模型只在「轮与轮之间」有动作机会，且经常忘。v26.3 决策日志 §5 自己埋了这条
   待办：「要强制就在 agent loop 加 hook 兜底」。

结论：让模型负责「定时报活」是把任务派给了它最不擅长、甚至物理上做不到的环节。

---

## 2. 决策清单

### 决策 1：心跳由代码触发，不靠模型自觉（解耦）

职责重划：
- **模型保留**：有语义内容的播报——起手 `info`、真正的阶段切换 `progress`、
  风险 `warning`、完成 `done`。这些需要理解任务才能产出，只能模型做。
- **代码接管**：纯「我还在，别以为挂了」的存活心跳。机械、无内容、且能在阻塞期触发。

后台守护线程在主线程被 `subprocess.run` 卡住的那几十秒里照常存活、照常报活——
这正是模型做不到的事。

### 决策 2：直连 `VoiceClient`，不 subprocess 调 CLI

`nano_voice_kit` 已有 `client.py:VoiceClient`（httpx 直连 Runtime FastAPI）。心跳线程
直接 `from nano_voice_kit.client import VoiceClient` 推 `/events`，零 subprocess fork
开销（心跳要轻、高频，fork 进程与此矛盾）。代价：nano 主线对 voice kit 产生一个
**软依赖**——用 try-import 降级：import 失败 / Runtime 没起 → 心跳整个不启，主任务
零影响。

### 决策 3：静默超时才播，不固定间隔硬播

触发条件三者全满足才推一条 `progress`：
1. `agent_busy.is_set()` 为 True（agent 正在跑 tool loop；复用 main.py 已有的 busy event）。
2. 距上次**心跳**播报超过阈值（默认 25s，env `VOICE_HEARTBEAT_SECONDS`，`0` 关闭）。
3. Runtime 启动时 `/health` 探通（不通就根本不启线程）。

模型正常播报时，voice kit 的 `progress` 队列策略（替换还没播的旧 progress，见
voice-runtime SKILL.md 表格）自然吸收偶发重叠——不堆积，最多偶尔多一句，可接受。

### 决策 4：心跳门控复用 v26.3 的 `is_fully_available`

只有 voice-runtime skill **完全可用**（`DASHSCOPE_API_KEY` 已设 + `terminal` 在）
才启心跳——和 v26.3 注入 directive 的门槛同源（`SkillMetadata.is_fully_available`）。
能力真用不了时绝不刷屏。判断逻辑：main.py 启动时查 skill_loader 里 voice-runtime 的
metadata，跑 `is_fully_available(available_tools)`，再叠加 `/health` 探活。

### 决策 5：心跳状态不进 `AgentRuntime`（不污染父子共享语义）

`AgentRuntime` 是父子（delegate）共享的真理源，承载 `cancel_token` / `session_tokens`。
心跳是父主进程独有、与子 agent 无关，放进去会污染语义。新建独立小对象
`VoiceHeartbeat`（agent/voice_heartbeat.py）持有自己的 `last_beat_ts` / `stop_event`
/ `VoiceClient` 句柄 / 阈值，生命周期跟 main loop 走。

### 决策 6：SKILL.md directive 瘦身——删掉那条做不到的「20s 自心跳」

v26.3 的 directive 里「维持约 20 秒一次的语音心跳」现在由代码兜底，从 directive
里删掉（保留起手 / 阶段 / 风险 / 完成的语义播报纪律）。让模型只背它背得动的部分，
遵守率反而回升。directive 末尾加一句说明：存活心跳由 runtime 自动维持，你只需在
**状态真正变化**时播报。

## 3. 落地

| 文件 | 改动 |
|------|------|
| `agent/voice_heartbeat.py`（新增） | `VoiceHeartbeat` 类：try-import VoiceClient + `/health` 探活 + 后台守护线程循环（醒来→查 busy & 超时→推 progress→刷新 last_beat）。全程 fail-safe，任何异常不冒泡。 |
| `main.py` | 启动时按门控（voice-runtime `is_fully_available` + `/health`）构造 `VoiceHeartbeat`；在 tool loop 的 `agent_busy.set()` 之后 / `clear()` 之前，告知心跳「本轮开始/结束」并刷新基准时间戳；退出时 `stop()`。**模型每次成功播报后无法回传时间戳**——心跳用自己独立的 `last_beat`，靠 voice kit 队列替换策略消化重叠（决策 3）。 |
| `skills/voice-runtime/SKILL.md` | frontmatter `inject_directive` 删「20s 自心跳」段，末尾加「存活心跳由 runtime 自动维持」说明；正文「何时播报」的心跳条同步改。 |
| `scripts/test_v26_4_voice_heartbeat.py`（新增） | 不变量：心跳线程在 busy+超时时推一条 / 非 busy 不推 / 未超时不推 / Runtime 不可达时不启（不抛）/ import 失败降级 / `VOICE_HEARTBEAT_SECONDS=0` 关闭 / `stop()` 后线程退出。用 fake VoiceClient 注入，不依赖真 Runtime。 |
| `docs/decisions/README.md` + `CLAUDE.md` | 追加 v26.4 索引行 + TL;DR 更新当前阶段。 |

线程模型：`VoiceHeartbeat` 起一个 `daemon=True` 线程，`while not stop_event.is_set()`
里 `stop_event.wait(tick)`（tick=1s）轮询。判断 busy 用 main.py 传入的
`threading.Event`：`set()` 表示 tool loop 运行中，`clear()` 表示回到 prompt。
`last_beat` 由心跳线程自己写、main loop 轮始重置，竞争窗口无害（最坏多/少播一拍）。

`VoiceClient.speak_intent` 内部 `httpx.Client(timeout=10)` 是阻塞的——但跑在心跳
**自己的线程**里，不阻塞 main loop。若 Runtime 中途挂了，speak 抛异常被心跳循环的
try 吃掉，记一次 warning 后继续（不反复刷错误）。

## 4. 验证计划

- 不变量测试（fake VoiceClient + 受控 busy/时钟）：≥7 项，覆盖触发矩阵 + 降级路径。
- 回归：v26.3（10/10）不破坏——directive 渲染逻辑没动，只改 SKILL.md 文本内容。
- 真机：起 Runtime + 设 `DASHSCOPE_API_KEY`，跑一个 sleep 60 的 terminal 命令，
  确认阻塞期间每 ~25s 听到一声存活心跳；不设 key 时心跳不启、无报错。

## 5. 待办 / 后续

- ⏳ 真机验证存活心跳在 terminal 长阻塞期的实际触发。
- 心跳文案目前固定（"还在处理，稍等"），后续可让它读最近一次 `[tool] <name>` 做
  更具体的存活语（"还在跑 xxx"）——但那要心跳线程能看到 tool loop 的最近动作，
  是增量增强，按需再做。

  的整段（v23.4），所以心跳在 delegate 期间也会触发，无需额外改动。
