# v26.2 — 参数/变量替换（仅安全 token，绝不做内联 shell）

> skill 现在能在 SKILL.md 正文里用 `${SKILL_DIR}` 引用自己的目录、`${SESSION_ID}`
> 引用当前会话——返回前做纯字符串替换，路径随仓库 clone 位置自适应。**源项目
> 还有 `!`cmd`` 内联 shell（执行任意命令），nano 从源头不移植。** 计划见
> [docs/Skill-system/skill-system-completion-plan.md](../Skill-system/skill-system-completion-plan.md) §7。

---

## 0. 一句话

v26.0 让 skill 能携带资源、v26.1 让 skill 能声明依赖，v26.2 让 skill 指令能
**引用运行期上下文**——skill 作者写 `${SKILL_DIR}/references/x.md` 而非硬编码
绝对路径，换台机器、换个 clone 路径仍然对。

## 1. 决策清单

### 决策 1（本档红线）：内联 shell 整个函数不移植

源项目 `agent/skill_preprocessing.py` 有两个机制，**风险等级天差地别**：

| 机制 | 行为 | 风险 | nano |
|------|------|------|------|
| `${...}` token 替换 | 纯字符串替换 | 安全 | **保留**（去 HERMES 前缀）|
| `` !`cmd` `` 内联 shell | `subprocess.run(["bash","-c",...])` | **执行任意命令** | **整个函数不写进来** |

源项目的内联 shell 默认 `inline_shell=False` 关闭、需 config 显式开。但
**「默认关闭」不等于「不存在」**——函数在代码里，就是一条「skill 文件 = 任意
代码执行」的攻击路径（一个被污染的 SKILL.md 即可触发）。nano 教学版连
`expand_inline_shell` / `run_inline_shell` 都不写，从源头消除这条路径。这不是
可配置项，是 §8 安全护栏的硬约束。

### 决策 2：token 白名单固定 2 个，不开放任意 env 名

`_TOKEN_RE` 只认 `${SKILL_DIR}` / `${SESSION_ID}`。**不做** `${任意ENV名}` 这类
开放替换。原因：开放替换一旦支持，`${OPENAI_API_KEY}` / `${ANTHROPIC_API_KEY}`
就会把密钥替进 SKILL.md 正文 → 进 context → 可能被日志/trajectory 落盘。白名单
固定 2 个让「能替什么」是闭集，密钥永远不在其中。

白名单外的 token（`${FOO}` / `${OPENAI_API_KEY}`）**不在正则捕获范围内**，天然
原样保留——不需要额外的「拒绝逻辑」，正则本身就是边界。

### 决策 3：无值的 token 原样保留，不替空串

`${SESSION_ID}` 在没有会话时（`session_id=None`）**原样留下** `${SESSION_ID}`，
而非替成空串。理由：原样保留让 skill 作者一眼看出「这里运行期没拿到值」，是可
排错的显式信号；替空串会把问题静默掩盖（作者看到 `sid=` 还以为替成功了）。
这与源项目「unresolved tokens are left in place so the author can spot them」一致。

### 决策 4：只替 SKILL.md 正文（tier 2），tier 3 资源不替

`view()` 过 token 替换；`read_resource()` 返回**原始内容**。原因：tier 3 资源
常是模板文件（`templates/report.md`），里面的 `${...}` 可能是**模板自身的语法**
（给下游模板引擎用），nano 不该越俎代庖替掉它。token 替换是「skill 指令引用
运行期上下文」的机制，只服务于指令正文，不服务于它携带的素材。

### 决策 5：session_id 来源——复用 v25.1 thread-local，不新增参数链

`skill_view` 工具 handler 从 `agent.logging.get_log_session()`（v25.1 的
thread-local 会话绑定）取 session_id，而非给工具调用协议加一个 session 参数。
原因：thread-local 已经是「当前线程属于哪个会话」的权威源（main loop 与
delegate 子线程天然隔离），复用它零成本且语义正确。`"-"` 哨兵（未绑定）归一成
`None` → 走「无值原样保留」分支。`/skill view` slash 则从 `ctx.current_session_id` 取。

### 决策 6：`view(name, session_id=None)` 默认 None 向后兼容

旧调用方（v21.x 单测、不关心会话的路径）调 `view(name)` 不传 session_id →
`${SESSION_ID}` 原样保留、`${SKILL_DIR}` 照常替。行为对增量调用方透明。

## 3. 裁剪（vs 源项目）

- **不做内联 shell**（安全红线，决策 1）—— 连函数都不移植
- 不做 `metadata.hermes.config` 配置变量替换（依赖 config.yaml 体系，nano 无）
- 不读 config.yaml 的 `skills.template_vars` 开关（nano token 替换始终开，无开关）
- token 白名单固定 2 个，不开放任意 env 名（决策 2）

## 4. 验证

`scripts/test_v26_2_token_subst.py` —— 8/8 不变量：

- **token 替换**（5）：`${SKILL_DIR}`→目录；`${SESSION_ID}` 有值替/无值留；未知
  `${FOO}` 原样；无 token 文本不变；`${OPENAI_API_KEY}` **不替**（即使该 env 真有值）
- **接入**（3）：`view()` 输出含替换后路径；`read_resource` 的 tier 3 资源**不**替；
  连续两个 token 都各自替换

回归：v26.1 10/10、v26.0 10/10、v21.3 13/13、v21.2 prompt_builder 15/15。

真跑：`SkillLoader('skills').view('plan', session_id='demo-sess')` →
SKILL.md 里 `${SKILL_DIR}` 被替成 skill 绝对目录、`${SKILL_DIR}` token 全部消失。

## 5. 决策一句话总结

| 决策 | 选项 | 没选 | 原因 |
|------|------|------|------|
| 内联 shell | **完全不移植** | 移植但默认关闭（源项目）| 教学版从源头杜绝「skill=任意代码执行」攻击面 |
| 替换范围 | 固定 2 token 白名单 | 开放任意 env 名 | 防 `${API_KEY}` 把密钥写进 context |
| 无值 token | 原样保留 | 替空串 | 原样保留是可排错的显式信号 |
| tier 3 资源 | 不替换 | 也替换 | 模板文件的 `${...}` 可能是模板自身语法 |
| session_id 来源 | 复用 v25.1 thread-local | 加工具协议参数 | thread-local 已是会话归属权威源，零成本 |
| 向后兼容 | `session_id=None` 默认 | 强制传参 | 旧调用方 `view(name)` 行为透明不变 |

本档收尾 v26 skill 子系统纵深补强档组（资源 → 门控 → 替换三层全部落地）。
