# v27.1 — 外部 Voice Orchestrator（host 只发送事实）

> 本档是 v27.0 `ProgressSupervisor` 废弃后的正式主线。主智能体不再调用语音工具，也不在宿主进程里判断“什么时候播 / 播几次 / 怎么说”。nano 主仓只负责发送受限 envelope 与 runtime phase lease；外部 Voice Orchestrator 负责调度、降噪、文案和调用 `nano_voice_kit`。

---

## 0. 一句话

v27.1 把语音能力从主 agent runtime 解耦：`main/tool/delegate/stream → TurnEventEnvelope + RuntimePhaseLease → VoiceEventSink → external voice-orchestrator`。host 只报事实，service 才拥有播报策略。

---

## 1. 为什么从 v27.0 改

v27.0 的 `AgentEventBus` 方向正确，但 `ProgressSupervisor` / `LLMPhraseProvider` 仍把策略放在主进程：

- 工具价值、低价值工具、cooldown、每轮上限、错误播报都硬编码在 Python；
- 主 agent transport chain 被复用来生成语音短句；
- `main.py` 要初始化 voice client / health probe / heartbeat fallback；
- skill directive 仍要求 assistant 通过 `terminal` 调 `nano-voice-say`；
- 长工具参数生成和父进程等待子 agent 这类“运行中 phase”仍不能被外部服务独立调度。

因此 v27.1 保留“事件化 + 安全 payload + side-channel 失败隔离”，删除宿主侧 voice policy。

---

## 2. 目标 / 非目标

目标：

- 主智能体零语音工具调用；
- 主进程不决定播报时机、次数、文案、工具重要性；
- envelope 包含最后一轮 user preview、最近 message preview、assistant/tool preview、active phase；
- phase lease 覆盖模型生成文本、模型生成工具参数、工具执行、父进程等待子 agent；
- 所有发送失败都不影响主 turn；
- 第一版只承诺流式路径的细粒度 activity。

非目标：

- 不在 nano 主仓实现完整 Voice Orchestrator 服务端；服务端策略放到 `nano_voice_kit` 或外部服务；
- 不发送完整消息、完整工具输出、文件内容、raw tool args、系统 prompt、原始 chain-of-thought；
- 不播放子 agent 内部细节；父进程只发送 aggregate child phase；
- 非流式 `chain.call()` 暂不承诺自然进度播报。

---

## 3. 新架构

```text
main.py / transports / ToolRegistry / delegate_task
        |
        | bounded TurnEventEnvelope + RuntimePhaseLease
        v
VoiceEventSink / VoiceOrchestratorClient
        |
        | HTTP JSON, fail-safe queue
        v
external voice-orchestrator
        |
        | policy / phrase / schedule / speak count
        v
nano_voice_kit Runtime
```

nano 主进程只做三件事：

1. 构造安全、截断、脱敏的 envelope；
2. 维护 phase lease，说明当前运行区间仍然活着；
3. 尽力发送，失败吞掉。

## 5. Envelope 边界

最小结构：

- identity：`schema_version` / `session_id` / `turn_id` / `event_type` / `timestamp`
- context：`last_user_message_preview` / 最近 N 条非 system message preview
- assistant_activity：可见文本 preview / safe reasoning activity label / next tool name
- tool：工具名、状态、耗时、result head/tail preview
- phase：phase name/status/lease id/elapsed/activity metadata
- safety：是否截断、是否脱敏、明确 omitted 列表

禁止发送：

- system prompt；
- raw tool args；
- raw terminal command/output；
- 文件全文；
- 子 agent transcript；
- 原始 chain-of-thought；
- 密钥、`.env`、绝对路径、stack trace。

---

## 6. Runtime Phase Lease

首批 phase：

- `assistant_generating_text`
- `assistant_generating_tool_call`
- `assistant_generating_tool_arguments`
- `tool_executing`
- `child_agent_running`

事件状态：

- `phase_started`
- `phase_activity`
- `phase_heartbeat`
- `phase_finished`
- `phase_error`
- `phase_cancelled`

关键点：phase lease 不是播报策略，只说明“这个运行区间仍然存在，并带有安全元信息”。

---

## 7. 两个卡死场景

### 7.1 长工具参数生成

OpenAI-compatible `delta.tool_calls[].function.arguments` 与 Anthropic `input_json_delta.partial_json` 现在会被转成 metadata-only 事件：

```text
tool_call_id / tool_name / argument_field / delta_chars / total_chars
```

不会发送参数正文，尤其不会发送 `write_file(content=...)` 的长内容。

### 7.2 父进程等待子 agent

`delegate_task` single/batch 都维护父级 `child_agent_running` phase。batch 路径从 `ThreadPoolExecutor.map` 改为 futures 完成循环，因此可以更新：

```text
mode / task_count / completed_count / running_count / failed_count
```

第一版不发送子 agent 内部工具、文件、模型文本、工具结果或 transcript。

## 8. 配置

host 侧只保留连接与预览边界：

```bash
VOICE_ORCHESTRATOR_ENABLED=0
VOICE_ORCHESTRATOR_URL=http://127.0.0.1:8766/v1/turn-events
VOICE_ORCHESTRATOR_TIMEOUT_SECONDS=0.5
VOICE_ORCHESTRATOR_QUEUE_SIZE=128
VOICE_ORCHESTRATOR_STREAM_ONLY=1
VOICE_ORCHESTRATOR_MAX_MESSAGE_PREVIEWS=4
VOICE_ORCHESTRATOR_MAX_MESSAGE_CHARS=800
VOICE_ORCHESTRATOR_MAX_TOOL_RESULT_CHARS=1200
VOICE_ORCHESTRATOR_SEND_MESSAGE_PREVIEW=1
VOICE_ORCHESTRATOR_SEND_TOOL_PREVIEW=1
```

不再有 host-side `VOICE_LLM_*`。progress gap、heartbeat、speech count、phrase LLM 等策略配置属于外部 orchestrator。
