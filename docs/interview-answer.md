# 面试回答：从零搭建 AI Agent 工具系统的架构设计

## 问题场景

> "介绍一个你从 0 到 1 设计的系统，体现你的架构能力。"

---

## 回答参考

我从零设计并实现了一个 AI Agent 的工具调用系统。这个系统要解决的核心问题是：Agent 需要调用外部工具（执行命令、读写文件、调用 API），但工具数量会不断增长，运行环境各不相同，而且 LLM 返回的参数经常有类型错误。

我没有一开始就设计一个大而全的架构，而是通过 6 次迭代，每次只解决当前最痛的问题：

**第一步是解耦。** 最初工具和 Agent 强耦合，加一个工具要改三处代码。我引入了注册表模式——工具文件 import 时自动注册 schema 和 handler，Agent 只通过 `dispatch(name, args)` 统一调用。这样加新工具只需要写一个文件，零侵入。

**第二步是按需暴露。** 所有工具都塞给 LLM 会浪费上下文。我设计了 Toolsets 分组机制，配合 `check_fn` 运行时探测可用性——比如 Docker 工具只在 Docker 安装的机器上才出现。这让同一份代码在不同环境自动适配。

**第三步是性能优化。** 每轮对话都遍历注册表、调 check_fn 太浪费。我设计了两层缓存：外层用 generation 计数器做 O(1) 失效判断（注册表没变就直接返回），内层用 30 秒 TTL 缓存 check_fn 结果（外部状态不会秒级变化）。同时引入 MCP 协议支持按需连接外部工具服务，连接后 generation 递增自动触发缓存失效。

**第四步是健壮性。** LLM 经常返回 `"42"` 而不是 `42`。我在 dispatch 层统一做类型强制转换——读取工具的 JSON Schema，自动把字符串转为期望类型，转换失败保留原值不抛异常。同时加了 async 桥接，让异步工具能在同步循环里透明执行。

**第五步是可扩展性。** 想加日志、限流、结果截断，每次都要改 dispatch 代码。我在 dispatch 流程中插入了三个钩子点：pre（可阻止执行）、post（观察）、transform（替换结果）。插件通过 `register/deregister` 管理生命周期，一个插件出错不影响其他插件。

最终的 dispatch 流程是：`coerce → pre_hook → handler → post_hook → transform → return`，每一层都是独立关注点，可以单独理解和测试。

**这个设计过程体现的思路是：** 不做过度设计，每一步都是被真实问题驱动的。注册表解决耦合，Toolsets 解决膨胀，缓存解决性能，coerce 解决健壮性，hooks 解决扩展性。每一层都是在上一层暴露问题后才引入的，而不是一开始就堆上去。

## 面试官可能的追问及应对

**Q: generation 计数器相比直接比较工具列表有什么优势？**

A: O(1) 比较一个整数，vs O(n) 比较整个列表。而且 generation 是单调递增的，任何变化（register、deregister、MCP 连接/断开）都会体现，不需要关心具体变了什么。

**Q: 为什么 MCP 工具和普通 async 工具用不同的异步方案？**

A: 场景不同。MCP 是长连接——session 要持续存在，所以需要一个持久的后台 event loop。普通 async 工具是一次性协程——调完就走，用 `asyncio.run()` 更简单。用同一个方案会让简单场景变复杂，或者让长连接场景不稳定。

**Q: 钩子系统为什么用"第一个非 None 替换"而不是链式 transform？**

A: 简单且够用。链式 transform 需要定义执行顺序、处理冲突，复杂度高。实际场景中 transform 通常只有一个插件在做（比如截断），"first wins"语义清晰，避免多个插件互相覆盖。

**Q: 如果要支持并行工具执行，架构需要怎么改？**

A: dispatch 本身不需要改——它是单次调用。并行化发生在调用层：用 ThreadPoolExecutor 并行调用多个 dispatch。需要注意的是 hooks 的线程安全（当前是单线程所以无锁），以及 async 工具在 worker 线程里需要 per-thread event loop 而不是共享一个。

**Q: coerce 放在 dispatch 层有没有坏处？**

A: 有。如果某个工具故意接收字符串类型的数字（比如电话号码 "13800138000"），coerce 会错误地转成 int。所以设计上只转换 schema 声明为非 string 类型的参数——如果 schema 写的是 string，就不会动它。这是 schema 驱动的，不是猜测。
