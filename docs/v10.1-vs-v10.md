# V10.1 vs V10 — 全维度差异对比

## 一句话

V10.1 是 V10 的"后端真实化"——服务端从 `dict + md5` 升级到 `pgvector + OpenAI embedding`，Provider 端 HTTP 时序 0 改动。这是 V7 抽出 ABC 时承诺的"两端独立演化"的最终兑现。

## 一、文件级变更

| 文件 | V10 → V10.1 |
|------|-------------|
| `docker-compose.yml` | **新增**（pgvector/pg16） |
| `scripts/init.sql` | **新增**（建表 + ivfflat 索引） |
| `scripts/mock_memory_server.py` | **完全重写**（dict→pgvector，md5→OpenAI embed） |
| `memory/remote_semantic.py` | **同步演进**（新增 budget/min_score/auto_retain 配置；请求时序不变） |
| `.env.example` | **追加**（DATABASE_URL / EMBEDDING_* / MEMORY_RECALL_BUDGET） |
| `pyproject.toml` | mock-server extras 加 psycopg/pgvector/dotenv；新增 `[tool.setuptools]` 显式 packages |
| `agent.py` | 从 env 读三个新配置注入 Provider；banner 改名 |

## 二、服务端深度对比

### 存储

| 维度 | V10 | V10.1 |
|------|-----|-------|
| 存储后端 | `dict[session_id, list[(text, vec)]]` | `memories(id, session_id, text, embedding vector(1536), created_at)` |
| 持久化 | 进程退出即丢 | 持久化 docker volume，重启不丢 |
| 索引 | 无 | btree(session_id) + ivfflat(embedding vector_cosine_ops, lists=100) |
| top-k 算法 | Python `scored.sort()` | SQL `ORDER BY embedding <=> $1 LIMIT k` |
| 阈值过滤 | 仅丢 score ≤ 0 | 应用层 `score >= min_score` |

### 向量

| 维度 | V10 | V10.1 |
|------|-----|-------|
| 来源 | `hashlib.md5(text).digest() → 16 维 float / 255` | OpenAI 兼容 `client.embeddings.create()` |
| 维度 | 固定 16 | 默认 1536（可改 `EMBEDDING_DIM` + 重建表） |
| 语义 | 无（同 hash → 同向量，但相似文本完全不相似） | 真语义（同义/近义文本余弦接近） |
| 端点切换 | 无（写死 md5） | 改 `EMBEDDING_BASE_URL` 一行即可（OpenAI / SiliconFlow / 本地 Ollama / vLLM） |

### 请求/响应契约

| 字段 | V10 | V10.1 |
|------|-----|-------|
| `RecallRequest.query` | 必填 | 必填（不变） |
| `RecallRequest.session_id` | 默认 `""` | 默认 `""`（不变） |
| `RecallRequest.k` | `int = 3` | `int \| None`（不传则走 budget） |
| `RecallRequest.budget` | — | **新增** `low/mid/high`，服务端映射为 k=2/5/10 |
| `RecallRequest.min_score` | — | **新增** 余弦阈值，默认 0.0 |
| `RecallResponse.hits[i].text` | 同 | 同 |
| `RecallResponse.hits[i].score` | `1 - cosine_distance`（Python 算） | `1 - cosine_distance`（SQL 算） |
| `SyncRequest` | `{user, assistant, session_id}` | 完全相同 |

**向后兼容**：V10 客户端调 V10.1 服务端 → budget 不传 → 服务端兜底 k=5，能跑。  
V10.1 客户端调 V10 服务端 → 多带的 budget/min_score 被 Pydantic V10 ignored → 能跑（但行为退化到 V10 的 top_k=3 + 无阈值）。

## 三、Provider 端深度对比

| 维度 | V10 | V10.1 |
|------|-----|-------|
| HTTP 调用代码 | `_client.post(/recall, ...)` `_client.post(/sync, ...)` | **完全相同**（仅 payload 字典多两个 key） |
| 调用时序 | prefetch → sync_turn | **完全相同** |
| 超时 | `timeout=5.0` | `timeout=15.0`（embedding API 比 hash 慢一档） |
| 构造参数 | `base_url, top_k=3, timeout=5.0` | + `budget="mid", min_score=0.0, auto_retain=True` |
| 错误处理 | warning 返空串 | **完全相同** |
| Manager 集成方式 | `add_provider(RemoteSemanticProvider(...))` | **完全相同** |

**`git diff v10..v10.1 -- memory/remote_semantic.py` 摘要**：
- 类签名新增 3 个 keyword args
- payload 字典新增 2 个 key
- 内部 `_budget` 加白名单校验
- 文档注释更新
- **零业务流程改动**

## 四、运行时复杂度对比

| 操作 | V10 | V10.1 |
|------|-----|-------|
| 启动依赖 | `fastapi + uvicorn`，单进程 | + docker (pgvector/pg16) + psycopg + pgvector + OpenAI 兼容端点 |
| 启动步骤 | 1 步 | 4 步（docker / pip / .env / server） |
| 首次启动耗时 | <1s | docker pull + init schema ≈ 10-30s |
| Sync 延迟 | <1ms（dict append） | ≈ 200-500ms（OpenAI embedding API + DB write） |
| Recall 延迟 | <5ms（dict 全扫） | ≈ 100-500ms（embedding API + pgvector ANN） |
| 跨重启持久化 | ❌ | ✅ |

V10.1 慢了 100x，但**真的能用**——召回的不是 hash 噪声而是语义相关条目。

## 五、Hindsight 路线对齐度

| Hindsight 概念 | V10 | V10.1 |
|---------------|-----|-------|
| `bank_id` 隔离 | session_id 凑合 | session_id 凑合 |
| `recall_budget=low/mid/high` | ❌ | ✅（同款命名） |
| `recall_min_score` | ❌ | ✅（同款行为） |
| `auto_retain` 开关 | ❌ | ✅ |
| `recall_max_tokens` | ❌ | ❌（nano 不做） |
| `tags` 过滤 | ❌ | ❌（nano 不做） |
| 实体抽取 / 知识图谱 | ❌ | ❌（生产复杂性） |
| 多模式（cloud/embedded/external） | ❌ | ❌（只做 external） |

V10.1 提取了 Hindsight 路线的"call shape"（API 参数命名 + budget 档位语义 + pgvector 存储），舍弃了运行时复杂性。

## 六、可演进方向（不在 V10.1 范围）

| 方向 | 改动点 | 对应源项目实现 |
|------|-------|----------------|
| 异步 sync | sync_turn 走线程池 + 队列，立刻返回 | hindsight `aretain_batch` + writer thread |
| Recall 预热 | queue_prefetch 在上一轮 tool loop 期间提前调 /recall | hindsight `queue_prefetch` + `_prefetch_thread` |
| 实体抽取 | server 端引入 LLM，把对话拆成事实条目存 | hindsight `retain` 内置 OpenAI 调用 |
| Tags 过滤 | RecallRequest 加 `tags: list[str]` + `tags_match` | hindsight `recall_kwargs["tags"]` |
| Reflect 综合 | /reflect 端点用 LLM 合成召回内容 | hindsight `client.areflect()` |
| 多 bank 隔离 | session_id → bank_id，多 session 共享 bank | hindsight `bank_id` |
| 嵌入缓存 | Provider 端 query 文本 LRU 缓存 embedding | 无对照 |

## 七、为什么这次演进比 V6→V7 / V7→V8 都小

V6-V10 每步引入一个**架构概念**（存储分离/接口抽象/编排器/生命周期/HTTP 边界）。  
V10→V10.1 只是**替换实现**——没引入新概念，只是把 mock 升级为生产组件。

这恰恰是想要的形态：**好的架构在替换实现时不需要新概念**。如果 V10.1 还要改 ABC、改 Manager、改钩子签名，说明 V7-V9 没抽好。事实上：
- `MemoryProvider` 接口：0 改
- `MemoryManager` 编排：0 改
- 生命周期钩子签名：0 改
- agent.py 主循环时序：0 改

**这一点本身就是 V7-V9 三个版本的最终验收。**
